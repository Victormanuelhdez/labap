APX Online

Transacción y librería

La transacción es el punto de entrada de la operación Online y coordina el flujo. La librería contiene operaciones de negocio reutilizables y acceso a datos, expuestas mediante una interfaz.

Recuerda: Transacción coordina; librería ejecuta.

Evita confundir: No concentres todo el negocio en un DTO ni dupliques una consulta en cada transacción.

DTO

Un Data Transfer Object representa y transporta los datos de la operación entre componentes. En el ejemplo APX aparece como un Bean de entidad comercial.

Recuerda: DTO = datos que viajan.

Evita confundir: DTO no equivale a tabla, conexión ni servicio de negocio.

Clase abstracta y parámetros

La clase abstracta de la transacción separa las operaciones de parámetros de entrada y salida de la lógica implementada por la transacción.

Recuerda: Parámetros separados del flujo.

Evita confundir: No confundas la generación de acceso a parámetros con implementar reglas de negocio.

setSeverity

setSeverity establece la gravedad de la notificación generada por una transacción.

Recuerda: Severity = gravedad.

Evita confundir: No establece el país, el tipo de transacción ni los datos de entrada.

Online frente a Batch

Online se apoya en transacciones, librerías y DTOs. Batch utiliza Jobs, librerías y DTOs. Ambos son capacidades del entorno APX.

Recuerda: Online: transacción. Batch: Job.

Evita confundir: Un Job no es una transacción Online.

APX CLI, Maven y OSGi

APX CLI y entorno local

CLI es una herramienta de línea de comandos para crear y operar componentes. El entorno local permite probar y depurar transacciones y Jobs antes de producción.

Recuerda: CLI = comandos; local = pruebas.

Evita confundir: Local no significa entorno productivo.

Comandos de práctica

apx init du-lib inicializa una unidad de despliegue de librería. apx send req envía una solicitud. En apx deploy local --runtime=online --country=ESP -y, ESP es el país España.

Recuerda: init crea; send envía; deploy despliega.

Evita confundir: ESP es país, no idioma. Los argumentos completos dependen del componente y versión de CLI.

JDBC Utility

La dependencia se declara en pom.xml. El ejemplo corregido identifica library-arc-osgi.xml, library-arc.xml y pom.xml como archivos configurados al añadir JDBC Utility.

Recuerda: JDBC conecta; pom declara dependencia.

Evita confundir: No cambies pom.xml por settings.xml en una pregunta de dependencias de la aplicación.

Ciclo Maven

compile compila; test ejecuta pruebas; package genera el artefacto; install además lo instala en el repositorio local. clean elimina normalmente target.

Recuerda: package genera; install instala.

Evita confundir: package no equivale a despliegue productivo.

OSGi y consola

OSGi administra módulos Java y su ciclo de vida. Import-Package declara paquetes requeridos. APX Operation Console es la herramienta web para operación, configuración y consulta de componentes y Jobs.

Recuerda: OSGi módulos; Console operación.

Evita confundir: La consola de operación no es el compilador ni la CLI.

APX Batch y Spring Batch

Job y Step

Un Job representa el proceso por lotes completo. Un Step representa una etapa de ese proceso. Puede implementarse orientado a chunks o con un Tasklet.

Recuerda: Job = proceso; Step = etapa.

Evita confundir: JobRepository no es un tipo de Step.

Reader, Processor y Writer

Reader lee elementos. Processor transforma, valida o filtra. Writer escribe los resultados del bloque. Reader devuelve null al terminar; Processor puede devolver null para filtrar.

Recuerda: Leer → procesar → escribir.

Evita confundir: null de Reader termina la entrada; null de Processor filtra un elemento.

Chunk y consistencia

Un chunk agrupa elementos en un bloque transaccional. Si la escritura falla, la configuración transaccional gobierna la reversión del bloque; chunks ya confirmados no se revierten automáticamente.

Recuerda: Chunk = bloque de confirmación.

Evita confundir: No asumas un único rollback para todo el histórico del Job.

Tasklet

Tasklet permite ejecutar una tarea concreta dentro de un Step, por ejemplo una preparación o limpieza.

Recuerda: Tasklet = tarea específica.

Evita confundir: No obliga a seguir Reader → Processor → Writer.

JobRepository y JobLauncher

JobRepository guarda metadatos de ejecuciones y estados. JobLauncher inicia un Job con parámetros. Una JobInstance se identifica por el Job y sus parámetros identificadores.

Recuerda: Repository registra; Launcher lanza.

Evita confundir: Los metadatos del proceso no son los datos comerciales procesados.

Java y orientación a objetos

JDK, JRE y JVM

JDK agrupa herramientas de desarrollo y ejecución. JRE es el entorno de ejecución y bibliotecas. JVM ejecuta el bytecode. javac convierte fuente .java en .class. La distribución concreta del JRE depende del proveedor y versión.

Recuerda: JDK desarrolla; JRE ejecuta; JVM interpreta bytecode.

Evita confundir: No uses javac como nombre de la máquina virtual.

Promoción numérica

byte y short se promocionan a int en operaciones aritméticas. Si interviene double, los operandos se promocionan a double. La división entre enteros descarta la parte fraccionaria.

Recuerda: Tipos pequeños → int; double domina.

Evita confundir: byte + byte no produce automáticamente byte.

String e igualdad

String es inmutable. Métodos como toUpperCase devuelven un nuevo valor. == compara referencias y equals compara contenido cuando la clase lo implementa de ese modo.

Recuerda: == referencia; equals contenido.

Evita confundir: No ignores la asignación del resultado de un método que devuelve String.

Herencia y polimorfismo

Una clase extiende una sola clase y puede implementar varias interfaces. La sobrescritura de métodos de instancia permite ejecutar la implementación del objeto real. No se puede reducir visibilidad al sobrescribir.

Recuerda: Tipo real elige el método sobrescrito.

Evita confundir: protected no puede reducirse a acceso de paquete en una sobrescritura.

Constructores

En Java 11, this(...) llama a otro constructor de la misma clase y super(...) al padre, como primera instrucción. El compilador genera un constructor por defecto únicamente si no declaras ningún constructor.

Recuerda: this mismo; super padre.

Evita confundir: Declarar un constructor con parámetros elimina el constructor automático sin parámetros.

Excepciones

Checked exige capturar o declarar. RuntimeException es unchecked. throw lanza y throws declara. finally normalmente se ejecuta al salir del bloque; devolver desde finally puede ocultar un retorno o error.

Recuerda: throw dispara; throws avisa.

Evita confundir: finally no es final. No trates salidas de System.out y System.err como un orden visual garantizado.

Interfaces funcionales y Optional

Una interfaz funcional tiene un único método abstracto. Predicate devuelve boolean; Function transforma; Consumer consume; Supplier produce. Optional representa presencia o ausencia; get sobre empty lanza una excepción.

Recuerda: Predicate pregunta; Function transforma.

Evita confundir: Optional no elimina automáticamente todos los NullPointerException.

Colecciones, Streams y lambdas

List, Set y Map

List guarda una secuencia y admite duplicados. Set evita duplicados. Map asocia claves únicas a valores. ArrayList mantiene orden de inserción y admite cambios; no ordena por valor automáticamente.

Recuerda: List secuencia; Set únicos; Map clave-valor.

Evita confundir: Orden de inserción no equivale a orden alfabético.

Comparable y Comparator

Comparable define compareTo y el orden natural en la clase. Comparator permite comparaciones externas distintas. TreeSet utiliza orden natural o un comparador.

Recuerda: Comparable dentro; Comparator fuera.

Evita confundir: No asumas que HashSet itera en orden de inserción.

equals y hashCode

Si dos objetos son iguales según equals, deben devolver el mismo hashCode. Un mismo hash puede corresponder a objetos diferentes.

Recuerda: Iguales → mismo hash.

Evita confundir: Mismo hash no implica igualdad.

Streams

filter selecciona; map transforma; distinct elimina duplicados. Son operaciones intermedias. collect, count y reduce consumen el flujo. Los Streams se evalúan de forma perezosa y no se reutilizan tras consumirlos.

Recuerda: Intermedias preparan; terminal consume.

Evita confundir: Stream.toList() no está disponible en Java 11; usa collect(Collectors.toList()).

Arrays.asList

Devuelve una lista de tamaño fijo respaldada por el arreglo. Puedes cambiar elementos con set, pero add o remove no están soportados.

Recuerda: Tamaño fijo ≠ totalmente inmutable.

Evita confundir: ArrayList y Arrays.asList no tienen la misma capacidad de modificar tamaño.

Patrones y arquitectura

Singleton, Strategy y State

Singleton controla una única instancia. Strategy representa algoritmos intercambiables. State permite cambiar el comportamiento según el estado interno.

Recuerda: Singleton uno; Strategy algoritmo; State estado.

Evita confundir: Cambiar algoritmo y cambiar estado son necesidades distintas.

Observer, Composite y Adapter

Observer notifica suscriptores. Composite representa jerarquías parte-todo. Adapter hace compatible una interfaz existente con otra requerida.

Recuerda: Observer avisa; Composite árbol; Adapter conecta.

Evita confundir: No confundir jerarquía de objetos con herencia de clases.

Command y Builder

Command encapsula una solicitud como objeto. Builder permite construir objetos complejos por pasos.

Recuerda: Command acción; Builder construcción.

Evita confundir: Crear objetos por etapas no es notificar eventos.

The Blob

El antipatrón concentra demasiadas responsabilidades en una clase o librería. El ejemplo propone redistribuir comportamiento según las entidades y responsabilidades para reducir acoplamiento y facilitar pruebas.

Recuerda: Blob = demasiado en uno.

Evita confundir: No confundir el antipatrón con el tipo de dato binario BLOB.

ASO y APX

En la arquitectura estudiada, ASO invoca APX y APX gobierna la operación y su acceso a datos. Un acceso directo de ASO que salta esa capa puede duplicar caminos y omitir reglas y controles.

Recuerda: Respeta al responsable de la operación.

Evita confundir: Aclara primero si las flechas de un diagrama representan llamadas, dependencias o respuestas.

Pruebas, datos y transacciones

Arrange, Act, Assert

Prepara datos y dependencias; ejecuta la unidad; verifica resultados, errores y efectos. Incluye casos positivos, negativos y límites relevantes.

Recuerda: Preparar → ejecutar → verificar.

Evita confundir: Nombrar JUnit y Mockito no explica las etapas de una prueba.

JUnit y Mockito

JUnit organiza pruebas y aserciones: assertEquals compara valores, assertSame identidad. Mockito simula dependencias: when/thenReturn prepara respuestas y verify comprueba interacciones.

Recuerda: JUnit verifica; Mockito aísla.

Evita confundir: Un mock no demuestra que la integración real con base de datos funcione.

ACID, commit y rollback

Atomicidad: todo o nada; consistencia: invariantes válidas; aislamiento: control de concurrencia; durabilidad: persistencia tras confirmación. COMMIT confirma y ROLLBACK revierte cambios no confirmados de su ámbito.

Recuerda: ACID protege la transacción.

Evita confundir: Un rollback local no deshace automáticamente un abono en un sistema externo.

Timeout e idempotencia

Un timeout no demuestra que la operación falló: pudo ejecutarse sin respuesta. Consulta el estado y usa la misma clave de idempotencia para reintentar sin duplicar el efecto.

Recuerda: Misma operación, misma clave.

Evita confundir: Crear un ID nuevo en cada reintento impide detectar duplicados.

JDBC, claves y HTTP

PreparedStatement parametriza valores SQL. Clave primaria identifica filas y clave foránea referencia otra clave. HTTP 401 indica ausencia de autenticación válida y 403 acceso prohibido.

Recuerda: 401 identidad; 403 permiso.

Evita confundir: Parametrizar valores no permite aceptar cualquier nombre dinámico de tabla.
